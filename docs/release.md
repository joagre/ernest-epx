# The release

What a release runs to be ready, and nothing else. Between releases a change runs `make test` before every commit (CLAUDE.md, *Tests*).

1. **A fresh clone builds and passes**, as [`full_review.md`](full_review.md)'s *How it runs* has it.
2. **The window tried by hand**, on a machine with a screen, since `make test` opens none: each example of `Epx.Window`'s page, and each program of `examples/` with the word `show`, run and looked at, and its window closed with Enter. The cold reader is among those who try.
3. **The readers** of [`full_review.md`](full_review.md), run as it runs them, with its briefs: for a release before the program is first recommended to others, K, the cold reader; from that release on, C, the code reader, beside it, over `src/`.
4. **The findings**, sorted and worked as [`full_review.md`](full_review.md)'s *The findings* says.
5. **The round:** once the findings are fixed, K again over the diff, from the commit the review started on to the release's commit, of what it reads: the lines the review's own fixes wrote there and no reader has read. The session reads the code's lines back as each agent returns them (CLAUDE.md, *The repository*).
6. **The note**, the release's section of `CHANGES.md`, first in the file and committed before the tag, which the release step copies as the notes of the release on GitHub so that it is written once: what the release is, naming no milestone, review or log entry, since its reader is a user; what a program or an operator of the previous release changes; the design's diff between the last release's tag and this one's; and one line a change naming the design's section where it is read. It restates no change, and its date stands in its heading alone.
7. **The release:** `VERSION` set, and with it the README's release, its archive's link and the floor that archive was built on; every exported declaration that appeared since the last release ending its doc block with its own `since`; the tag, signed, `git tag -s v<version>`, with an SSH key GitHub holds as a signing key, so that GitHub marks it verified; and the archive `make release` writes, `build/<name>-<version>.tar.gz`, published beside the tag with its checksum, `build/<name>-<version>.tar.gz.sha256`, so that another repository's `make lib` can name it and a user can check it. The session runs the release to the tag and the archive; the push and the release on GitHub wait for the user's word (CLAUDE.md, *Done*).
8. **`language_feedback.md`'s lines carried to Ernest**, as CLAUDE.md's *Defects and gaps* says, so that a release leaves nothing the language has not heard.
