# The release

What a release runs to be ready, and nothing else. Between releases a change runs `make test` before every commit (CLAUDE.md, *Tests*).

1. **A fresh clone builds and passes:** `git clone --recursive`, then `make test`, in a directory of its own.
2. **The window tried by hand**, on a machine with a screen, since `make test` opens none: each example of `Epx.Window`'s page, and each program of `examples/` with the word `show`, run and looked at, and its window closed with Enter. The cold reader is among those who try.
3. **The readers**, each a session of its own, given its brief and the files it reads and nothing that argues for them: for a release before the program is first recommended to others, one cold reader, who reads `README.md` and runs the program as a user would; from that release on, a code reader beside it, who reads `src/` against `design.md`, the report's §0 and Appendix E.0's shape rules. Each runs on the model `CLAUDE.md` gives its kind of reader. Each hands in a numbered list, most serious first: a finding gives its place, a short quote, what is wrong, and a one-line fix.
4. **The findings:** a defect is fixed or planned in a milestone; clarity is fixed where it is cheap, and otherwise dropped. The lines stand in `findings.md` until each is done, and the commit messages say which. A decision among them is argued after the log is searched for the decision it may sharpen (CLAUDE.md, *Before code*), and a name a reader lists is decided after the word is searched across the design, the code and the pages, never from its module alone.
5. **The round:** once the findings are fixed, the cold reader again over the diff from the commit the review started on to the release's commit, the lines the review's own fixes wrote and no reader has read.
6. **The release:** `VERSION` set, and with it the README's release, its archive's link and the floor that archive was built on; every exported declaration that appeared since the last release ending its doc block with its own `since`; the tag, signed, `git tag -s v<version>`, with an SSH key GitHub holds as a signing key, so that GitHub marks it verified; and the archive `make release` writes, `build/<name>-<version>.tar.gz`, published beside the tag with its checksum, `build/<name>-<version>.tar.gz.sha256`, so that another repository's `make lib` can name it and a user can check it.
7. **The note**, the release's section of `CHANGES.md`, first in the file and committed before the tag, which the release step copies as the notes of the release on GitHub so that it is written once: what the release is, naming no milestone, review or log entry, since its reader is a user; what a program or an operator of the previous release changes; the design's diff between the last release's tag and this one's; and one line a change naming the design's section where it is read. It restates no change, and its date stands in its heading alone.
8. **`language_feedback.md`'s lines carried to Ernest**, so that a release leaves nothing the language has not heard.
