# Findings of the release review, 0.1.0

The two readers of [`release.md`](release.md), a cold reader and a code reader, read commit `4cab93c` on 2026-10-20. Each line is a finding with its verdict: `fix`, made before the release; `plan`, a line of `plan.md`; `drop`, with its reason. The file goes when every line is done. The readers' third parts, what the language made harder, are `language_feedback.md`'s lines 3 to 9.

## Defects

1. **A large pixmap crashes the node, and a far coordinate lands wrong.** epx computes a pixmap's bytes, `bytes_per_row * height`, in 32 bits, so `create(65536, 65536, Argb)` allocates 15 bytes and the first write aborts the VM; above 2 GiB a pixel's address is computed in `int` and a write segfaults; every pixmap has a transform, so epx turns a coordinate into a `float` and one past ±2^24 lands on a neighbor; and a right edge is `x + width - 1` in `int`, so `fillArea(p, 1, 0, 2147483647, 1, c)` writes nothing. `fix`: the library bounds what it hands epx and faults with its own cause before the call: a coordinate and a size from −16,777,216 to 16,777,216, and a pixmap whose bytes, the row's times the height, reach 2^31; `design.md` §4 and §5 state the bounds, the module's doc block states them in a paragraph of their own, and `epx_bugs.md` gains the size overflow and the `int` edge as reports 7 and 8.
2. **The archive does not work as a dependency** for epx's `ebin`, which lies under the archive's own `lib/`, which a consumer's load path does not reach. `fix`: `README.md` says a program that uses the library lists epx among its own `ERL_DEPS`, and names the archive as the operator's.
3. **`scale` reads the source's clip**, and what it writes from a clipped source is neither the source nor the clip scaled. `fix`: the page and §4 name `scale` among the functions that read the source's clip and state that its result from a clipped source is not stated: a program sets the source's clip to the whole pixmap first.
4. **`fadeArea`'s formula is false at fade 255**, where epx takes the source's alpha itself. `fix`: the sentence.
5. **The blends' two rectangles overlapping in one pixmap** give neither the placement rule's result nor `copyArea`'s. `fix`: §4 and each blend's doc block say the two rectangles must not overlap in one pixmap, their result then not stated; `copyArea` alone handles the overlap.
6. **A long call holds a scheduler**: epx's NIFs run on the host's normal schedulers, and `scale` of an 8192 by 8192 pixmap holds one for four seconds. `fix`: a paragraph of the module's doc block, *A call's cost*, says that a call runs on the host's scheduler until it ends and nothing else runs there meanwhile, with `scale`, `toPpm` and `create` of a large pixmap as the slow ones.
7. **A negative width or height faults with epx's cause**, where Ernest's §7.4 and its standard library read a count below 0 as none. `fix`: a width or a height below 0 reads and writes nothing, decided in Ernest before the call, as `List.take` has it; the Errors sections lose the sentence.
8. **tree_db is on the load path and not needed**: only `epxy.erl` reaches it, and no pixmap function does. `fix`: the submodule goes, `ERL_DEPS` is `epx` alone, the page, the headers, the examples' README and `ACKNOWLEDGMENTS.md` say epx alone; the page says epx's `ebin` is needed when the program runs.
9. **The Errors sections are incomplete**: `copy` and `toPpm` fault when the host cannot allocate and say nothing; the others name only a negative size, and only two name the coordinate bound. `fix`: every Errors section names every fault its function raises, after finding 1's bounds and finding 7's change.
10. **`toPpm`'s row in §1's table says it calls no epx function**, and it calls five, and its temporary pixmap is filled for nothing. `fix`: `toPpm` makes its temporary pixmap without the fill, through the private `rawCreate`, since `copyTo` writes every pixel; the row names it as Ernest over `create`, `copyTo` and `getPixels`, and §1's "at most once" excepts it.
11. **The tests claim more than they test**: `operations` runs five of seventeen on opaque pixels; the target clip of `putPixels`, `scale` and the area functions, `copy`'s clip reset, `setClip`'s empty clip, `format`'s fault on a foreign-made pixmap and §3's exact comparison have no test. `fix`: all seventeen on translucent pixels, and a case for each rule named.
12. **Nothing checks a doc block's `// =>` lines**: a wrong value passes `make test`. `plan`: a tool of the template's, for every library, which `plan.md`'s milestone 2 names as waiting on the template, and a line of language feedback, since `ern test` could run them as Ernest's own tests do.
13. **The misplacement at the source's clip is documented, not closed.** `drop`: decided with the user on 2026-10-20, the log's *The clip correction dropped*; the sentence stays until epx fixes it.
14. **The Mandelbrot header leaves `draw` out of the parts that act.** `fix`.

## Clarity

1. **The README gives a program outside the repository no way in**: the load path stands only in the examples, relative to the root, and the README's "`lib/`, which is the whole load path" leaves out `build`. `fix`: a *Using it* section with the `--load-path` flags and one `ern build` and `ern run` pair.
2. **The README never names the manual page.** `fix`: the release commits `docs/man/`, and the README names `docs/man/epx.md` as the page in its first paragraph.
3. **An opaque source comes out one short** under `SrcOver`, `Src` and `blendArea` at 255, by the `/ 256` formulas, which the page does not say. `fix`: one sentence under `Operation` and `blendArea`; `copyArea` and `Copy` draw it exactly.
4. **The clip paragraph hides the shift** of a source rectangle that begins outside the clip, and `copyArea`'s sentence took three readings. `fix`: the paragraph names the exception in one sentence, and `copyArea`'s doc block gives the one-row example.
5. **`Xor` alone has no arithmetic.** `fix`: its alpha is the two alphas summed less twice their product scaled by 256, rounded down, and its channels as `SrcOut` and `DstIn` blended by the source's alpha, as the other constructors have theirs.
6. **The README calls the library "the program"** three times. `fix`.
7. **`make` gives a bare error when no `ern` is found.** `fix`: the template's `version` target says so, built as the template's commit of 2026-10-20; the Makefile here takes it.
8. **`make test` looks like it fails when it passes**: the checker's line reads as an error, and each expected fault prints its report. `fix` for the checker, which heads its list as a notice, from the template; the fault reports are the language's, feedback 124.
9. **`Epx.Rgb` and `Epx.rgb` differ only by case.** `fix`: one sentence under `Format` saying which is which.
10. **The examples cite `design.md`**, which a user does not have. `fix`: they cite the page by its headings.
11. **The example headers write a `.ppm` at the repository's root.** `fix`: under `build/`.
12. **`EXAMPLE_SUFFIX`'s comment is part of its value**, so every written name ends in spaces. `fix`: the comment on its own line, in the template too.
13. **`design.md` §4's second paragraph is 136 words** and holds four rules. `fix`: split at each turn.
14. **`getPixels`'s comment says epx answers its whole memory** for any empty rectangle, and only at 0, 0 it does. `fix`: the comment and §1's sentence say so.
15. **"Operation" names two concepts**, the library's functions and the `Operation` type. `fix`: the functions are called functions, in the page and the design.
16. **Names**: `source` and `target` for colors and `from` and `into` for pixmaps in the `operations` test, `raster` for a pixmap, `rawInfoTerm` for what it is made of, `isChannel` for a fade, `written` for a function that acts, `step` for a count. `fix`: `sourceColor` and `targetColor`, `source` and `target`, `rgbPixmap`, `rawPixelFormat`, `isByte`, `write`, `count`.
17. **`toPpm`'s doc sentence is hard to parse**, and its example shows bare bytes. `fix`: §6's wording and an example compared with `String.toUtf8("P6\n1 1\n255\n") <> <<0, 0, 0>>`.
18. **`pixelSize` ends in `_ -> 4`**, so a format added later silently takes four bytes, and `formats` restates the constructors by hand. `fix`: match all six; `formats` stays, since a sum type's constructors cannot be enumerated, feedback line 7.
19. **The Coordinates paragraph states the faults too**, two matters in one. `fix`: with defect 1, a paragraph each.
20. **The examples**: mandelbrot's `draw` is a formatter staircase, and sierpinski's `Epx.rgb(x, y, 255 - x)` faults at a size past 256 without saying so. `fix`: name the row function; the size's comment states the bound, and the color is computed from the size.
21. **The Makefile's long lines**, seven past 100 characters. `fix`: wrapped, in the template too.
22. **Concurrent writes interleave**: epx takes no lock, so two calls on one pixmap interleave pixel by pixel and a read sees half a fill. `fix`: the sentence in *In place and shared* and §2.
