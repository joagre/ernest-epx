# Defects found in epx

The defects the library met in epx that its pinned commit has not fixed, each written as a report for epx's tracker, as first filed and numbered 2026-10-20 to 2026-10-23 (`docs/log.md`, *The first cut built*, *The reports verified*, *The fixes verified*). The numbers are those of the first filing, which the design and the log cite: the reports epx fixed at 23a0ed2, 1 to 4, 6, 9 to 11, 13 to 18 and 20 to 22, went when the submodule moved to 02a0eaf, which has them (the log's *The pin moved*).

Each of these stays until a commit of epx the library builds has its fix; [`epx_asks.md`](epx_asks.md) is the same list in the tracker's form.

Most serious first: 12, 23 and 25 draw wrong where a program cannot tell, and 24 shows memory, each where the library draws; 7 crashes, 8 writes nothing and 19 refuses silently, each beyond the library's bounds; 5 answers memory from a call the library never makes.

12. **An ellipse's ring is malformed at its top and bottom.** `epx_draw_ellipse_border` with a border of 1 or 2, and past a radius of 65535, draws a lone pixel outside the ring, lets the fill show through below it, and makes the ring thicker there than at the sides: a 20 by 20 ring's second row is one pixel where the filled circle's is seven. The overflow past a radius of 65535 and the double blending of `blend` were fixed at 23a0ed2. The library states the ring as epx draws it (`design.md` §9).
23. **An ellipse of even width or height is one pixel larger.** `epx_ellipse.c` takes `x + 2*a` as the right edge, so an ellipse 20 wide at `x` 1 covers columns 1 to 21, as one 21 wide does, and the same for its height. The library states the size as epx draws it (`design.md` §9). Found 2026-10-23, at 1377959 and 23a0ed2 alike.
25. **A diagonal line of width 1 leaves out its first pixel.** `pixmap_draw_line(P, Gc, 0, 0, 5, 3)` draws `1, 1`, `2, 1`, `3, 2`, `4, 2` and `5, 3` and not `0, 0`, whatever the line's style, where a horizontal or vertical line keeps both ends; `nfirst` and `nlast` change nothing for a single line. The library states it (`design.md` §9). Found 2026-10-23, at 1377959 and 23a0ed2 alike.
24. **A window's copy off the screen is never cleared.** After a draw, the parts of the window not drawn into show what the X server's memory held, `17, 2, 19` where the background was white. The library states nothing of what a new window shows (`design.md` §11). Found 2026-10-23, at 1377959 and 23a0ed2 alike.
7. **The area functions take their row stride as an `int`.** `epx_fill_area(uint8_t*, int dst_wb, ...)` and its kin, so `pixmap_create(600000000, 2, argb)` is taken and `pixmap_fill_area(P, 0, 0, 1, 2, C)` crashes the VM. The pixmap's bytes and a pixel's address are counted in 64 bits since 23a0ed2, and a row wider than 4 GiB is refused. The library bounds a pixmap's bytes below 2 GiB and a coordinate at 16777216 (`design.md` §4, §5).
8. **A width that rounds to 2^32 writes nothing.** `get_dim` converts with `(unsigned int) round(wf)`, so `pixmap_fill_area(P, 1, 0, 4294967295, 1, C)` writes nothing where it covers the pixmap; the edge past 2^31 − 1 is computed in 64 bits since 23a0ed2 and fills. The library bounds a width at 16777216 (`design.md` §4).
19. **A window wider than X takes is refused silently.** `window_create` with a width of 40000, 70000 or 16777216 answers a window, and `window_attach`, `window_sync`, `pixmap_draw` and `window_detach` each answer `ok`, with no window on the screen and `window_info` reporting the width asked; a width or height of 0 raises `badarg` since 23a0ed2, and no size hangs. The library bounds a window's width and height to 1 to 32767 (`design.md` §11).
5. **An empty `pixmap_get_pixels` answers the pixmap's live memory.** `pixmap_get_pixels(P, 0, 0, 0, 0)` is the shortcut for every pixel with its alignment, as the C comment says, and answers a binary over the pixmap's own memory, 32 bytes for a 2 by 2 pixmap, uninitialized before the first fill and changing as the pixmap is written, which no documentation states; the binary is made from `src->res` since 23a0ed2, and the VM lives. The library answers no bytes for an empty rectangle without calling epx (`design.md` §4).
