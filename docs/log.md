# Decisions

The dated rationale for the design and the plan, newest last, and what was rejected. Never normative: the design says what the program is, and the plan what is built when. An entry says what was decided, the principle of the report's §0 that decided it, and what would change it.

## Begun from the template

*2026-10-20.* The repository was begun from `ernest-template` at its tag `v0.1.0`, whose `CLAUDE.md` and `tools/docs.ern` are refreshed from there and not edited here. The way of working is the template's; a change to it goes to the template first. The library is the first repository begun from the template, so what the copy teaches about the template goes back to it: the first lesson is that a dependency that is Erlang, epx itself, is not what `make lib` fetches, which the entry below decides.

## epx and tree_db as submodules

*2026-10-20.* epx and tree_db are read-only git submodules under `erl/`, pinned to a commit each, built by their own `make` and linked under `lib/` as `ebin` and `priv`, so that the load path, which `ern run` adds to the host's code path, lets the host find epx's NIF from `priv/` beside `ebin/`. A copy of the trees was rejected: it loses where the code came from and drags epx's C into this repository. A fetch by rebar3 was rejected: epx's build is its own Makefile, its port configuration is rebar2's, its tree_db dependency is unpinned, and rebar3 is not on the machine. Principle 2, one way to bring in Erlang, the host's own, and the template's `lib/` kept as the one place a program loads from. Tried before being written: a pixmap made, filled red and read as `#(255, 255, 0, 0)` from a scratch program. What would change it: a dependency tool of Ernest's, the template's proposal's fourth ask of the language.

## The first cut built

*2026-10-20.* Built by an agent from the decided proposal, read back whole, and closed with these decisions, each where the proposal was silent or epx was not what it guessed. Tried first, each edge of the proposal's section 4 against the NIF: epx answers opaque black for a read outside the pixmap, clips a write, clamps a channel and does not mask it, and crashes the VM on a sub-pixmap's coordinates, on a scroll past the width and on an unsupported format name, which `epx_bugs.md` records as reports.

`sub` and `scroll` are left out until epx is fixed, since a function that can crash the node is no function: principle 1. A new pixmap is filled with 0, one pass over its pixels, since epx leaves the memory as the host gave it and a program would read what a last run left: principle 1. `putPixels` faults on bytes of the wrong size, where epx writes nothing or reads past them, and an alpha or a fade outside 0 to 255 faults as a channel does, where epx takes anything above as 255: decision 5 of the proposal applied to each, principle 1. An empty `getPixels` answers no bytes without the call, since epx answers its live memory. `getPixel` outside the clip answers opaque black as epx does, documented and not made an `Optional`, since the shim is the host function exactly and the clip is the caller's own setting. The clip is not read by `fill`, `flip`, `copyTo` and `getPixels`, as epx has it, documented.

The five area operations read the source's clip and move the target's corner before the call, since epx cuts the source's rectangle at the clip without moving the target's and the pixels land wrong (`epx_bugs.md` 6). The cost is stated and not hidden: about twice a small area operation, 96 to 253 ms over 200,000 one-pixel copies and 140 to 296 ms over 32 by 32; whether it stays is the plan's milestone 2 decision 1. A test's comment, not a doc block, names the design section it covers, since a doc block puts the test on the module's page: the template's rule changed with it.

## The clip correction dropped

*2026-10-20.* The five area operations call epx's functions exactly, and the correction that read the source's clip and moved the target's corner before each call is gone: a shim is the host function exactly, and what Ernest adds costs a fraction of the host's operation, where the correction cost a call of its own and doubled a small area operation. What epx does with a source rectangle that begins outside the source's clip, cut to the clip and landed as if it were not, is stated in `design.md` §4 and in each operation's doc block, so that a program begins the rectangle within the clip and nothing is hidden: principle 1 satisfied by the sentence rather than by code. `epx_bugs.md` 6 is the report; when epx fixes it, the sentence goes.

## Cook's Sampling

*2026-10-21.* The proposal as decided drew `m` shadow rays and `k` glossy rays at every hit of every branch, and counted at sixteen samples that is about 127,000 ray operations a pixel, nineteen hours on one worker and four on eight, against the minutes the proposal itself stated.
